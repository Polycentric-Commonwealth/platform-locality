# Locality platform

The reference platform for a **Locality** in the [Polycentric Commonwealth](https://github.com/Polycentric-Commonwealth/foundation): cities, towns and villages, where most people meet government day to day. There will be tens of thousands of instances, many with small budgets and little technical staff, so it must be the simplest platform to install and run, with a hosted option alongside self-hosting.

Its core stays small. Modules are optional and installed one at a time, so a village of 2,000 can run only council meetings and service requests while a large city runs everything.

## Planned first stage

- A public ledger of council decisions, budgets and contracts, useful to a city today without any Commonwealth.
- Council meetings, agendas, motions, votes and minutes.
- Service requests from residents.

The full list of planned modules is in the [platforms plan, section 7](https://github.com/Polycentric-Commonwealth/foundation/blob/main/docs/design/platforms-plan.md#7-locality-platform).

## Status

Not started. The first stage is planned in the [platforms plan](https://github.com/Polycentric-Commonwealth/foundation/blob/main/docs/design/platforms-plan.md#10-build-roadmap-and-open-questions). It will use the same stack and shared [foundation](https://github.com/Polycentric-Commonwealth/foundation) library as the [State platform](https://github.com/Polycentric-Commonwealth/platform-state): Go, SQLite or PostgreSQL, and server-rendered HTML ([decision 0004](https://github.com/Polycentric-Commonwealth/foundation/blob/main/decisions/0004-technology-stack.md)).
